凍結された世界モデルは「ズレた世界」でも役に立つか？

  • 主論文RSI-Anything: Unlocking Recursive Self-Improvement with World ModelsTaoyong Cui, Pinxian Zeng, Wanghan Xu, Hao Xiao, Shuhan Xue, Qiang Gao ほか（計11名） ・ arXiv preprint, 2026年10月https://arxiv.org/abs/2610.13912

仮説

  • H1：世界モデル（予測表）が正しい世界では、公式の infer.py（期待改善量EIで選ぶ）はランダム探索より少ない実験回数で最良条件に到達する。
  • H2：世界モデルの予測と真の収率の相関が低い「ズレた世界」では、EIの優位は縮む（または消える）。→ 論文が強調する「予測が外れ始めたら世界モデル自体を直す」（5〜6段階目）が必要な理由を確かめる。

追加コードの説明（B-1）
  • 公開データには真の収率が入っていない（suzuki_prior.json は世界モデルの予測値と不確かさだけ）。
  • そこで「真の収率」を次の式で模擬します。rho が予測の正しさを表すつまみです。
    真の収率 = rho × 予測値 + (1 − rho) × (予測値をシャッフルしたもの) + 不確かさ × 正規ノイズ
    • rho = 1.0：世界モデルがほぼ正しい世界
    • rho = 0.5：半分ズレた世界
    • rho = 0.0：予測が当てにならない世界

# 🆕 追加コード B-1：予測表を読み込み、仮想の「真の収率」を作る関数import numpy as np, subprocess, matplotlib.pyplot as pltfrom scipy.stats import spearmanr prior = json.load(open("tasks/reaction_optimization/assets/suzuki_prior.json"))C = prior["candidates"]mu = np.array([c["predicted_yield_percent"] for c in C])            # 世界モデルの予測sd = np.array([c["calibrated_std_percent_points"] for c in C])      # 予測の不確かさN = len(C)print("候補数:", N, " 予測収率の最大:", mu.max().round(2)) def make_world(rho, seed):    r = np.random.default_rng(seed)    y = rho * mu + (1 - rho) * r.permutation(mu) + r.normal(0, 1, N) * sd    return np.clip(y, 0, 100) for rho in [1.0, 0.5, 0.0]:    print(f"rho={rho}: 予測と真値の順位相関 = {spearmanr(mu, make_world(rho, 0)).correlation:.2f}")

3つの戦略を同じ条件（初期観測8回、合計30回まで）で比較します。

  • EI（公式 infer.py）：チュートリアルのスクリプトを subprocess で毎回呼び出し、提案された条件を「実験」します（--output を省くと結果がJSONで標準出力に出る、とREADMEにある）
  • 貪欲法：予測値が最大の未実験条件を選ぶ（不確かさを無視）
  • ランダム：未実験の条件からランダムに選ぶ

考察のヒント（【C】）
  • rho=1.0 で EI が最速なら H1を支持。論文の評価（10回目で最適条件に到達）と比べてどうか？
  • rho=0.0 で EI とランダムの差が縮めば H2を支持。これは「予測表が凍結されていて世界モデルを直さない」この公開デモの限界であり、論文の 5（学習）・6（保持） の段階が必要な理由になる。
  • 作成時の試運転（世界2つ）では EI と貪欲法の結果が完全に一致した。README にあるとおり予測（平均・不確かさ）は凍結されていて観測で更新されないので、EI が「探索」として働く余地が小さい。これも「学習しない世界モデル」の限界として書ける。
  • わからなかったこと（例）：JEPA の潜在空間で予測するとなぜ少ないデータで済むのか／世界モデルを「直すべきか」をどう判断するのか（論文の信頼性判定）。

仮説

  • H1：自己対戦の世代を重ねるほど、固定の相手（貪欲プレイヤー）への勝率が上がる（＝自己改善が起きる）。
  • H2：採用ゲートあり（updateThreshold=0.6：旧版に60%以上勝ったら採用）は、ゲートなし（0.0：常に採用）より世代間で強さが後退しにくい。

追加コードの説明（B-1）
  • Coach.learn() はそのまま使い、numIters=1 で1世代ずつ呼び出します（学習データの履歴 trainExamplesHistory は Coach の中に残るので、続きから学習が進みます）。
  • 各世代のあと、次の2つを記録します。
    1. 採用されたか：採用時だけ best.pth.tar が更新されるので、ファイルの更新時刻で判定
    2. 強さ：その時点のネットを使ったMCTSプレイヤー vs 貪欲プレイヤー（10局）の勝率
  • これを updateThreshold = 0.6（ゲートあり）と 0.0（ゲートなし＝常に採用）で行います。

論文

  • 関連DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language ModelsZhihong Shao, Peiyi Wang, Qihao Zhu, Runxin Xu, Junxiao Song, Xiao Bi ほか（計11名） ・ arXiv preprint, 2024年2月https://arxiv.org/abs/2402.03300

仮説

  • H1：正解報酬だけで学習すると、平均報酬（正答率）が少しずつ上がる。
  • H2：「長く書くほど得をする」報酬を足すと、モデルは正答率を上げずに出力を長くする方向へ進む（報酬ハッキング＝グッドハートの法則）。

追加コードの説明（B-1）
  • TRL の reward_funcs には複数の報酬関数をリストで渡せます。そこで、正解報酬に加えて

  • 正解報酬（0か1）と同じくらいの大きさの「長さボーナス」を与えるのがポイントです。

    APPENDIX前提知識の要点

    表現（埋め込み）
    画像や文章を、意味を保ったまま数字の並び（ベクトル）に変えたもの。
    自己教師あり学習
    ラベルなしで、データの一部を隠して当てるなどの問題を自分で作って学ぶ方法。
    線形プローブ
    表現を固定し、単純な線形分類器だけで精度を測る評価方法。
    世界モデル
    「この行動をとったら次に何が起きるか」を予測する、AI の中のシミュレーター。
    RSI の6段階
    提案 → 予測 → 選択 → 評価 → 学習 → 保持（RSI-Anything 論文の整理）。保持は「本当に良くなった時だけ採用する」ゲート。
    報酬ハッキング
    評価基準の抜け穴を突いて、本来の目的を達成せずに点数だけ上げること。
    JEPA
    隠した部分や未来の画素ではなく、表現を予測する方式（ヤン・ルカン氏が提唱）。細部より意味を学びやすい。
    崩壊（collapse）
    すべての入力に同じ表現を出すズルの解。EMA、VICReg（分散・共分散の正則化）、SIGReg（ガウス分布に近づける）で防ぐ。
    計画（MPC・CEM）
    世界モデルの中で行動列を試し、ゴールの表現に最も近づく行動を選ぶ。最初の1手だけ実行して計画し直す。
